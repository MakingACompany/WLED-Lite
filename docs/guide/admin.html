§1 Orientation

WLED-Lite is a fork of WLED tailored for a custom lighted-sign company. It splits the original busy UI into:

  • User UI (/) — the slim "Lantern" interface for end customers: power, brightness, color, effect, timer, schedule, segments.
  • Admin UI (/settings/*, /wled-lite/*) — everything else, PIN-gated.

Default credentials

  • AP SSID: WLED-Lite-AP
  • AP password: wled1234 (upstream default; intentionally kept — maintainer sets each device up before delivery)
  • Admin PIN: set during the 3-step welcome wizard. Never shipped in source. See §12 Welcome wizard.
  • OTA password: default empty; can be set in Security & Updates.

Reaching the admin UI

  1. From the slim UI, tap the gear icon in the top-right.
  2. Enter the admin PIN. The full settings hub appears.

Direct URLs (you'll be prompted for the PIN if not already authenticated):

  • http://your-sign.local/settings — hub
  • http://your-sign.local/wled-lite/segments — custom segment editor
  • http://your-sign.local/welcome — first-run wizard (forced when no PIN is set)
  • http://your-sign.local/reset — soft reboot (PIN-gated)
    • Authentication model: WLED-Lite reuses upstream's settingsPIN. The PIN gates /settings/*, /edit, /update, /upload, /reset, and /json?cfg. The user UI (/) and the narrow scope-limited endpoints (/json/si, /wled-lite/schedule) are intentionally not gated so the end user can still operate the sign without ever being asked for a PIN.

§3 WiFi & Network

/settings/wifi

Wi-Fi setup

Network SSID + Password

Connects the controller to the home / customer Wi-Fi. After save, the device joins as a station and the captive AP eventually disappears.

Static IP / gateway / subnet

Optional. Leave blank for DHCP. Recommended: use a router reservation by MAC instead of setting static here, so the customer's router can hand out a stable address that survives a factory reset.

AP SSID + Password

Defaults to WLED-Lite-AP / wled1234. Used when the configured network is unreachable. Don't disable the AP — it's the recovery path.

mDNS / network hostname

Default: wled-XXXXXX (last 3 bytes of MAC). Set a friendly name per device (e.g. labb-sign) so the customer can type labb-sign.local.

WLED Broadcast Port

UDP 21324. Shared with Realtime, ESP-NOW, and Multicast/E1.31. Don't change unless coexisting with another WLED install on the same LAN that uses the same port.

Improv

Adalight / Improv onboarding over USB serial. We keep it enabled (saves writing custom onboarding firmware).

DMX is NOT compiled in. Upstream wled.cpp:448–450 hard-codes GPIO2 as the DMX TX pin whenever WLED_ENABLE_DMX is defined, which collides with our default LED-data pin on the XIAO Plus. If a specific commercial deployment needs DMX output, spin up a separate env (e.g. xiao_esp32s3_plus_dmx) with WLED_ENABLE_DMX defined and pick a different DATA_PINS default. Network DMX (Art-Net / E1.31 inbound) still works via Sync Interfaces.

§4 LED & Hardware

/settings/leds — per-device LED bus configuration. The build-flag defaults set up a single bus on GPIO2 with 30 WS2812 pixels; this page is where you adapt that to the actual sign.

LED outputs (per bus)

GPIO

The data pin driving this strip. See §14 pinout for the XIAO Plus pin map.

Type

WS281x / SK6812 / APA102 / etc. Most signs use WS2812 RGB or WS2812 RGBW.

Count

Pixels on this bus.

Start

Global pixel index this bus represents. Buses are concatenated into one big virtual strip; segments and effects index into that virtual strip.

Reverse

Mirror the bus left-to-right. Handy when you wired the strip backwards.

Off Refresh

Keep refreshing data when LEDs are off. Usually fine to leave on; turn off to save a tiny amount of CPU.

Brightness limiter / ABL

Auto-Brightness Limiter math caps current draw based on PSU rating × max amps per LED. We also have an INA219 hardware sensor (see §10.1) acting as a real-measurement safety net on top.

LED transitions

Default 0.7s crossfade. Leave alone unless a customer complains about flicker on color change.

Color & gamma

Brightness gamma + RGB-channel gamma on/off. WLED-Lite defaults match upstream; leave them.

Multiple buses

Press Add LED output to add additional buses. The XIAO Plus carrier breaks out 8 candidate LED pins (GPIO 4, 7, 8, 9, 10, 11, 12, 13) — see §14. WLED's max for ESP32-S3 is 12 buses (4 RMT + 8 I2S/LCD channels).

§5 Segments (WLED-Lite custom)

/wled-lite/segments — custom admin page that lets you carve the strip into named regions. The end user sees these as pills in the slim UI.

What this page does

  • Renders a table of segment {name, start, stop} rows.
  • POSTs the array back to /json/state with the seg payload — same backing storage as upstream's segment system, so it persists in cfg.json.
  • Also writes preset 248 (the boot preset) so segment geometry survives reboot even without state-change-triggered cfg save.

Defining segments

Name

What the end user sees on the pill. Keep short. Names with letter+trailing-digit (B1, Top12) render with subscript in the slim UI; underlying name is unchanged.

Start / Stop

Pixel indices on the strip, zero-based, half-open. A 50-pixel region starts at 0, stops at 50 (covers pixels 0..49).

Edge cases

  • Single segment — the Section card is hidden in the slim UI. Add a second segment to make it appear.
  • 5+ segments — slim UI auto-collapses into [All] [Letters ▸]. No admin action needed; threshold is hard-coded in index.js.
  • Per-segment brightness — not exposed in the slim UI. Brightness is treated as global.

Source: wled00/wled_lite_segments.{h,cpp}. See docs/segments.md.

§6 Pin Info

/settings/pins — read-only diagnostic page that shows the current GPIO allocation. Useful when adding a new bus or button to confirm what's already taken.

§7 User Interface

/settings/ui — drastically slimmed compared to upstream. We removed the 8-toggle theme/checkbox clutter that confused end users.

Server description

The friendly name shown in the slim UI footer ("WLED-Lite" by default). Set per-device to make support easier ("LABB Sign", "Dad's Workshop", etc.).

Save

That's it. All other upstream UI toggles (dark mode toggle, theme picker, layouts) were stripped — the slim UI is opinionated and doesn't need them.

§8 Sync Interfaces

/settings/sync — controls how this controller talks to other controllers or external lighting systems.

WLED Broadcast (UDP 21324)

Send notifications

Default ON in WLED-Lite (we flip it from upstream's false via WLED_LITE_SYNC_DEFAULTS). Two devices on the same Wi-Fi mirror automatically.

Receive notifications

Default ON. Receive sync packets from peers.

Sync groups (8-bit mask)

Group 0x01 by default. Devices only sync with peers that share at least one bit.

ESP-NOW

Wi-Fi-less peer-to-peer for in-store displays / sync. Opt-in per device (off by default for security + power). When on, devices in the same group sync without a router.

Multicast / Real-time

Art-Net, E1.31 (sACN), DDP, TPM2 inbound. Used when a stage controller is driving the sign. Set the universe + start address; map to a segment via the LED config.

MQTT

Compiled in but UI hidden by default. If a deployment needs Home Assistant integration, surface the MQTT panel by removing the relevant display:none in settings_sync.htm (or just point the customer at MQTT broker setup directly).

See docs/multi-controller-sync.md for the full protocol notes.

§9 Time & Macros

/settings/time — time, timezone, sunrise/sunset, countdown effect, timer/macro automation.

NTP (WLED-Lite defaults)

Get time from NTP server

Default ON (WLED_NTP_ENABLED=true).

NTP server

Default time.nist.gov (NIST .gov server). Reliable in the US; doesn't require pool.ntp.org reachability. Change to pool.ntp.org for non-US deployments if .nist.gov is slow.

Sync interval

5 minutes (NTP_SYNC_INTERVAL=300UL). Keeps drift under a minute for "lights at 6 pm" schedules.

Time zone

Pick from dropdown. WLED uses POSIX TZ rules so DST is handled automatically.

NTP-only design decision. There is no manual "set current time" UI. Rationale: smart-outlet users cut all power so the controller has no clock to keep anyway, and any power-outage scenario that takes the controller down likely also takes the router down. If NTP is unreachable, the daily schedule simply doesn't fire until it returns. Don't add manual time entry without revisiting this trade-off.

Sunrise / Sunset

Set latitude + longitude; controller computes local sunrise/sunset and can fire timers relative to them ("on at sunset −15 min"). Useful for outdoor signs.

Countdown

Sets a target date/time for the Countdown effect. Does not set the system clock. Common confusion: these fields look like a clock-set control but they only feed the countdown effect.

Timers (upstream)

Up to 8 entries: {hour, minute, weekday-bitmask, preset id}. WLED-Lite's daily-schedule feature writes two of these (one for preset 250 = Daily ON, one for preset 249 = Daily OFF) via the user-facing slim UI. Don't manually edit timers that the slim UI created — re-saving the schedule will overwrite them.

Macros / Presets

Reserved preset IDs in WLED-Lite:

  • 248 — boot preset (segment geometry, written by segments admin save).
  • 249 — "Daily OFF" (written by /wled-lite/schedule).
  • 250 — "Daily ON" (written by /wled-lite/schedule).

See docs/scheduling.md for the full state machine.

§10 Usermods

/settings/um — configuration UI for any usermods compiled in. WLED-Lite's custom_usermods currently is audioreactive INA219 (audioreactive is inherited from upstream's xiao base; we don't use the mic on a sign but the FX library expects the symbols to exist).

INA219 current sensor

Hardware safety net: measures actual current on the I2C bus and clamps brightness if the strip exceeds the configured cap. Auto-detects on I2C addresses 0x40 / 0x41 / 0x44 / 0x45. Coexists with other I2C devices (OLED, etc.).

Enabled

Master toggle. Off by default; turn on once you've actually wired the sensor.

I2C address

Auto, 0x40, 0x41, 0x44, 0x45. Leave on Auto unless you've manually set the address via solder jumpers.

Shunt resistance

Match the value of the on-board shunt resistor. Most INA219 breakout boards ship with 0.1 Ω.

Max current (A)

The cap. When measured current exceeds max × 110%, brightness is reduced proportionally on the next 200 ms poll.

Hysteresis

How far under the cap the current must drop before brightness recovers. Stops thrash near the limit.

Source: usermods/INA219/ (mirrors upstream's INA226_v2). See docs/current-limit-ina219.md.

§11 Security & Updates

/settings/sec

Settings PIN

Gates /settings/*, /edit, /update, /upload, /reset, /json?cfg. Set per-device during the welcome wizard. To change:

  1. Enter current PIN.
  2. Type new PIN twice.
  3. Save.
If you forget the PIN: there's no recovery. Wipe the device (USB reflash with erase-flash + write-flash of merged-flash.bin) and re-onboard. See §16 Flashing.

OTA

OTA lock

Master OTA enable. When on, /update requires the OTA password.

OTA password

Separate from the settings PIN. Default empty.

ArduinoOTA

Espressif's IDE-driven OTA. Useful during dev; leave off in production.

Backup / Restore

Download cfg.json + presets.json via /edit before any risky operation. To restore, upload back via the same page.

Factory reset

"Reset" button erases cfg.json and presets.json from LittleFS. The Wi-Fi credentials, PIN, segments, schedule, and all timers are wiped. Use when re-deploying to a new customer.

§12 Welcome wizard (WLED-Lite custom)

/welcome — 3-step first-run flow. / redirects here automatically when no PIN is set (WLED_LITE_SECURITY_GATES).

  1. Step 1: Wi-Fi. Pick the customer's network, enter password. Device joins as STA on save.
  2. Step 2: Device name. Friendly hostname (becomes {name}.local).
  3. Step 3: Admin PIN. Set + confirm. Once a PIN exists, / stops redirecting to /welcome.
Re-running the wizard: only happens on PIN-less devices. To force it again, clear the PIN (/settings/sec with empty new-PIN) or factory-reset (/reset).

§13 Daily schedule mechanism

The slim UI's Daily schedule card POSTs to /wled-lite/schedule. This endpoint is not PIN-gated by design — the end user is supposed to set their own schedule without knowing the admin PIN, but they only get a tightly scoped API:

  • Save the current device state as preset 250 ("Daily ON").
  • Save an off-state as preset 249 ("Daily OFF").
  • Add/replace two entries in the timers vector that fire those presets at the requested times, every day.

Request body: {"on":"HH:MM","off":"HH:MM"} (24-hour). To clear: {"clear":true}.

Persistence: timers in cfg.json, presets in presets.json. Both survive reboot.

Source: wled00/wled_lite_schedule.{h,cpp}. See docs/scheduling.md.

§14 XIAO ESP32-S3 Plus pinout

The carrier board around the Seeed XIAO Plus uses this default GPIO map. Override per device in /settings/leds and /settings/pins.

GPIOXIAO labelPurposeDefault use
1D0Button 1short = cycle effect; long = enter brightness mode
2D1LED data (primary)DATA_PINS=2; 1 bus, 30 px, WS2812 RGB
4D3Button 2short = cycle palette; long = power toggle
5D4I²C SDAINA219, OLED, fan PWM driver, sensors
6D5I²C SCLsame bus as above
7–13D6 + Plus headerLED data (extra)Add as additional buses via /settings/leds
38–42Plus headerReserved / expansionUnused — available for sensors, OLED CS, etc.
43, 44HW UART TX/RXUART debug (or Status LED on 44)USB-CDC handles serial; GPIO44 doubles as STATUSLED (boot/AP/error/connected)

Status LED behavior (GPIO44)

  • Solid — connected, normal operation.
  • Slow blink — connecting to Wi-Fi.
  • Fast blink — AP mode (no Wi-Fi configured or unreachable).
  • Off — boot, or sub-system error.

See docs/hardware-pinmap.md and docs/button-bindings.md.

§16 Flashing the firmware

Pre-built binaries

Checked-in under firmware/<env>/ after each meaningful build. Each env folder contains:

  • firmware.bin — for OTA via /update
  • merged-flash.bin — first-time USB flash (bootloader + partition table + app, all in one)

First-time USB flash (Linux/macOS)

esptool --chip esp32s3 --port /dev/ttyACM0 --baud 460800 erase-flash
esptool --chip esp32s3 --port /dev/ttyACM0 --baud 460800 \
  --before default-reset --after hard-reset \
  write-flash --flash-mode dio --flash-size 16MB \
  0x0 firmware/xiao_esp32s3_plus/merged-flash.bin
Use --flash-mode dio, not qio. Puya flash on the XIAO Plus can't QIO before the second-stage bootloader initializes it. Using qio in write-flash or merge-bin bootloops the device.

First-time USB flash (Windows)

See docs/flash-from-windows.md.

Piecemeal flash (if merged-flash.bin bootloops)

esptool --chip esp32s3 --port /dev/ttyACM0 --baud 460800 \
  --before default-reset --after hard-reset \
  write-flash --flash-mode dio --flash-size 16MB \
  0x0      .pio/build/xiao_esp32s3_plus/bootloader.bin \
  0x8000   .pio/build/xiao_esp32s3_plus/partitions.bin \
  0xe000   ~/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin \
  0x10000  .pio/build/xiao_esp32s3_plus/firmware.bin

OTA

  1. Open /update (or /settings → Security & Updates → Update).
  2. Upload firmware/<env>/firmware.bin.
  3. Device reboots into the new image automatically.

The OTA header must match WLED_RELEASE_NAME — flashing a xiao_esp32s3_plus_8MB binary onto a 16MB env is rejected.

§17 Maintenance procedures

Re-deploy to a new customer

  1. Connect to controller as you (current customer's Wi-Fi if accessible, else AP fallback after factory-reset).
  2. Go to Security & Updates → Factory Reset.
  3. Power-cycle. Device boots into AP mode; welcome wizard waits at /welcome.
  4. Reconfigure Wi-Fi, name, PIN.
  5. Set up segments + schedule if needed.

Recover from a boot loop

  1. USB-flash merged-flash.bin for the matching env. See §16.
  2. Watch serial (USB-CDC) for the cause of the previous loop.
  3. If a bad cfg.json is the cause: hold both buttons during boot to force AP mode without reading config (TBD: verify upstream behavior; otherwise factory-reset over USB by erasing flash entirely).

Diagnose Wi-Fi issues

  1. If the controller doesn't appear on the network for > 90 s, it's probably in AP fallback. Check phone Wi-Fi for WLED-Lite-AP.
  2. Status LED on GPIO44 — see §14 for its blink codes.
  3. USB serial at 115200 prints connection attempts.

Pull an upstream-WLED merge

See docs/upstream-sync.md. Monthly playbook with conflict guides for platformio.ini, package.json, wled.h, button.cpp, FX.cpp.

Build from source

Linux/macOS:

~/.local/bin/pio run -e xiao_esp32s3_plus
~/.local/bin/pio run -e xiao_esp32s3_plus -t upload

Windows: docs/dev-setup-windows.md.

PlatformIO ≥ 6 is required (Ubuntu's apt-shipped 4.x is too old — install via pip install --user platformio).
